# 五子棋 · Three.js · 不会输的 AI

一个可以直接在浏览器里玩的 3D 五子棋：Three.js 负责画面，纯手写的 α-β 搜索引擎负责下棋。

## 运行

```bash
node server.js          # 然后浏览器打开 http://localhost:5174
```

Windows 下直接双击 `start.bat` 也行（会自动开浏览器）。
> 因为用了 ES Module，必须通过 http 打开，不能直接双击 index.html（file:// 会被浏览器拦截）。

## 目录

```
index.html        页面：Three.js 场景、棋盘/棋子、交互、UI
engine.js         五子棋 AI 引擎（纯逻辑，浏览器 / Node 都能跑）
selftest.mjs      引擎自测：战术题 + 批量对局（node selftest.mjs [局数] [每步毫秒]）
strengthtest.mjs  棋力梯度测试：固定节点数的强弱对战（可复现）
server.js         零依赖静态服务器
lib/              three.js（已下载到本地，可离线运行）
```

## 操作

- **左键点击** 落子
- **按住拖动** 旋转视角，**滚轮** 缩放
- 按钮：重新开始 / 撤销一步 / 让 AI 先手（你执白）

默认你执黑先行。HUD 里会显示 AI 每步搜了多少层、多少节点、耗时。

## AI 是怎么做到"不输"的

引擎按四道防线工作，任何一步都从第 1 层往下依次判断：

| 层 | 内容 | 作用 |
|---|---|---|
| 1 | 自己能连五 | 直接赢 |
| 2 | 对手能连五 | 必须堵 |
| 3 | VCF 搜索（连续冲四） | 自己有没有"冲四→冲四→…→连五"的强制杀；有就直接杀 |
| 4 | 迭代加深 α-β 搜索（默认 6~8 层） | 主搜索，选出全局最优着 |
| 5 | VCF 安全校验 | 把"下完之后对手能连续冲四取胜"的着法全部排除 |

几条关键的工程取舍：

- **棋型评估**：横/竖/斜/反斜共 88 条线各自维护增量分数，落子只重算经过它的 4 条线；
  并用 `3^9` 预计算表 O(1) 得到"在某点落子的棋型分"，用来给着法排序，让 α-β 剪枝效率最大化。
- **防守加权**：评估函数里对手分 ×1.15，宁可少进攻也绝不漏防。
- **着法排序**：候选点分数 = 己方棋型分 + 0.9 × 对手棋型分，所以"自己成五""堵对手五"
  这类关键手天然排在最前面，永远不会被候选数上限截掉。
- **VCF（连续冲四）**：进攻方只下"四"，防守方每步只有唯一解，分支极小，因此能搜到 8~10 层深，
  足以看穿人类常见的连续冲四杀棋。

自测结果（`node selftest.mjs 25 100`）：50 局对"会堵四的贪心机器人"全胜；
固定节点数的强弱对战（`node strengthtest.mjs 40000 6000`）中，搜得深的一方 6:0 全胜。

## 一点说明

自由规则（无禁手）的五子棋已经被证明是**先手必胜**的，所以"后手 AI 绝对不输"在数学上不可能做到
（任何一步走错都只是时间问题）。实践中的结论是：

- 它不会漏掉任何一手成五/堵五；
- 它不会让对手形成活四，也不会被 8 层以内的连续冲四（VCF）杀掉；
- 人类玩家想赢它，需要走出比它搜索更深的连续杀棋——门槛非常高。

如果想拿到"绝对不会输"的确定性，可以点 **让 AI 先手**，或者给游戏加上禁手规则。
